# Orchestrator runbook — md-to-pdf-ponytail-harness

The A/B against `md-to-pdf-ponytail` (read that runbook for everything shared):
SAME task, SAME pinned base, SAME `/ponytail full` mandate, **plus one added
variable** — the packet explicitly mandates full engineering-harness-loop
engagement ("not skippable under the minimalism doctrine"). Motivated by batch
3's finding: ponytail alone produced 0/4 loop conduct (no observe, no retro, no
seams). This variant measures whether an explicit carve-out restores the loop,
and what it costs.

## What differs from `md-to-pdf-ponytail`

- **The packet names `/eng-harness-flow`** alongside `/ponytail` — both are the
  variables under test, not leaks. Hooks, verbs, and seam vocabulary stay
  hidden (the skill teaches them; A3/A4/A9–A12 score whether they actually ran).
- **A3 is `required`** (process — marks importance; a process fail never caps).
- **A13's judged prompt carries the dual-mandate note**: harness conduct is not
  an "unforced addition" here; judge minimalism on the task solution itself.
- **Expect DL-005 relief, not cure**: loop verbs open capture windows, so the
  telemetry lane should see more than batch 3's single segment — still
  cross-check raw events before judging any fail.
- **Resolve ids are A7/A8** (extension help / PDF validator), same as
  `md-to-pdf-ponytail`.
- **Comparison axes for the rollup**: loop conduct restored? (A3/A4/A10/A11 vs
  batch 3's 0/4) · cost delta vs batch-3 ponytail (the price of the carve-out) ·
  minimalism fidelity unchanged? (A13 vs batch 3) · validator quality (A14).

Everything else — hygiene, spawn-inside-worktree, canary, F18 contract,
gate-conduct policy, scoring, judged cross-check discipline, telemetry sync
before teardown, F12 teardown — is identical to the `md-to-pdf-ponytail`
runbook. Follow it.
