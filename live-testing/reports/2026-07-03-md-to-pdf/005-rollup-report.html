Lazy, plus the loop: what a minimalism doctrine with a mandated harness recovers — and what only full process buys

Orchestrated eval, 15 runs total · headline comparison: 6 paired runs, 3 models × 2 doctrines · GitHub Copilot CLI (GPT-5.5, Claude Sonnet 5, Claude Opus 4.8) · same repo, same pinned base commit, identical blind task packets · orchestrator: Claude Fable 5 · scenarios, ledgers & per-run reports committed in-repo.

Abstract. We compare two working doctrines on an identical cold-start engineering task (a validated markdown→PDF harness extension with rendered mermaid): Flow — a mandated full SDD pipeline (research→plan→implement→review→ship), and Pony+Harness — a mandated minimalism doctrine (/ponytail full) with a one-sentence carve-out making the repo's engineering-harness improvement loop non-skippable. Both doctrines shipped working, validated extensions on every run (capability 1.00, 6/6). Pony+Harness cost 31–56% of Flow's credits and 44–64% of its wall time, and retained the improvement loop's durable outputs (in-flight observations, drained retro records with encoded findings). What it did not reproduce: Flow's pre-code defect interception (a security issue caught before implementation), its native stage semantics, and — under the tightest budget — one subject's test discipline. Process, measured this way, is not one dial but a portfolio: the loop can be bought à la carte for ~15–33% of session time, while review-stage defect interception appears to be what the remaining ×2–3 actually purchases.

1Setup

Each subject receives a blind packet: the task, its mandate(s), and a comms protocol — never the scoring. Worktrees are cut at one pinned base commit; subjects are spawned inside them; an orchestrator answers gates under a fixed conduct policy (accept step offers, answer scope questions identically, never choose methods, never prompt toward scored behaviours). Runs are scored by committed scenarios on two independent axes — capability (the artifact works: verb registers, the subject's own validator re-executed fresh on unseen input) and process (mandated conduct actually happened) — with three-valued rows (pass/fail/unknown, unknown excluded from scores) plus a rubric-driven judged layer filled only from verified artifacts: diffs, dependency deltas, raw session event streams, re-executed commands. Never subject prose.

The load-bearing difference is when defects get caught. Flow's only-of-its-kind result: a security issue intercepted before a line of code existed, because a validation stage examined the plan. Pony+Harness's defect catches are real but reactive — they happened because one model's personal culture is to break things on purpose during build. One is a property of the doctrine; the other is a property of the model. If your risk profile needs interception you can rely on across models, that is the thing the remaining ×2–3 buys.

Budget competition is real. The dual mandate produced the family's only two discipline regressions: GPT-5.5 (tightest budget) dropped the unit test its ponytail-alone run had left, and Opus broke the cohort's zero-dependency record. Mandates are not additive — they draw from one budget, and what gets displaced is whatever the model values least.

6Limitations

n=1 per cell — every number is a direction, not a distribution; same-base re-runs would tighten Wilson intervals on the pass rates. One task at one size: a single-extension build is minimalism's home turf; Flow's insurance premium is priced for larger, riskier work, and this experiment prices the premium, not the payout.
