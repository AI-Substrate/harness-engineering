All three retro records are real documents with real findings: GPT-5.5 captured the cold-worktree dist/ gap and a linked-worktree doctor blind spot; Sonnet encoded two green-but-wrong tool behaviours it discovered empirically (mermaid's HTML labels render invisibly outside Chromium — fixed with htmlLabels:false; pandoc/weasyprint drops unresolvable images at exit 0, only visible on stderr — now scanned per-diagram) with status:encoded and a suggested_encoding for the harness docs; Opus filed magic-wand MW-001 proposing a ctx.execJson() helper for binary-IO subprocesses. The trade the mandates made

  1. restoredLoop conduct went from 0/4 to 3/3 — observe, drain, records, both skills genuinely invoked (raw-event verified, every subject) — and telemetry visibility recovered with it (7 segments each vs batch 3's single segment; loop verbs open capture windows, DL-005 relief as predicted).
  2. displacedGPT-5.5 dropped its unit test. Its batch-3 run left a 2-case vitest; this run left none — validation lives only in the runtime path. Under the tightest budget, the two mandates competed and the check discipline lost.
  3. erodedOpus's minimalism gave way. Two new npm devDeps + a 64-line how-doc + README edits, where its own batch-3 run had proven installed tools sufficed. Scored an honest fail on A13.ladder-adherence — the only judged fail in the ponytail family. The engineering itself is strong (parse≠render honored: mermaid.parse is syntax-only, so it renders with real Chromium and validates the PDF bytes; a real-Chromium e2e in just checks); the ladder was not.
  4. heldSonnet held both mandates at once — zero deps AND full loop AND the batch's best verification. The dual mandate is satisfiable; it just wasn't free for everyone.
