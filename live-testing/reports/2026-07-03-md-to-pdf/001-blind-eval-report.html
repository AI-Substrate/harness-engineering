Insights, ranked by how much they should change what we do

01

Nobody follows the flow unprompted

Zero of four subjects invoked the-flow. One (GPT-5.5) touched eng-harness-flow, once. This is not a cheap-model problem — it is every model, at every tier, when blind and autonomous. The SDD flow is currently orchestrator-carried, not ambient practice.

Evidence: native transcripts (skill.invoked events; Skill tool_use scan) · n=4 · single scenario, single run each — direction is clear, magnitude needs replication.

02

Capability has converged; method is the differentiator

Four different models produced four completely different working pipelines — all validated, all inside 12.2–15.8 minutes. The blind packet achieved genuine method diversity, which is exactly what makes the eval measure approach rather than recall.

Evidence: flow-eval reports A6/A7/A8 pass ×4; A11 judged PASS ×4 · n=4.

03

Same model, different harness ≈ same performance, wildly different observability

Sonnet 5 on Copilot vs Claude Code: 14.9 vs 15.5 minutes, 105 vs 94 tool calls. The harness barely moved the outcome — but Claude Code exposes complete token accounting while Copilot exposes only credit counts (token payloads leave the machine unlogged).

Evidence: events.jsonl vs transcript JSONL correlation · n=1 pair — the cleanest single-variable comparison in the set, still one trial.

04

Cache reads are ~99% of token volume

The Claude Code subject generated 89,884 fresh in+out tokens but read 11,759,373 from cache. Context re-reading, not generation, is where the volume lives — cost optimization should target context shape, not output length.

Evidence: transcript usage sums, deduped by message id · n=1 session.

05

Cadence is a model fingerprint

Opus 4.8: 51 turns, 51 tool calls — precisely one tool per stride. Copilot-Sonnet 5: 106 turns at the same wall-clock. GPT-5.5 batches more tools per turn (84 across 55). A stable per-model signature would be usable as an anomaly signal in telemetry.

Evidence: events.jsonl turn/tool counts · n=4, one run each.

06

On Copilot credits, Sonnet 5 was the economical one

335 AIC vs Opus 4.8's 483 and GPT-5.5's 506¹ for the same passing outcome. Within one billing unit and one harness, that ordering is directly actionable for default-model choice on bounded tasks.

Evidence: pane cost footers captured pre-teardown · n=3 · credit multipliers differ per model, so this ranks spend, not compute.

What the reporting system proved — and what unlocks it

The full chain ran from committed git refs alone: session save --source git-ref → report → report-render (four labelled columns) → insights (seven sections). Its best behavior was honest degradation: v1 segments carry no tokens, skills, or stages, and the system said so — zeros with n and caveats, empty sections — rather than inventing numbers.

The single unlock: bump the scenario's base.ref to a current tag. Every session then captures env-joined, token-bearing, skill-aware segments, and three things light up at once: stage economics and skill breakdowns in the insights layer, the eval's entire process lane (A1–A5, A9, A10 resolve to real pass/fail), and the cross-model --compare board with populated cost rows.

Appendix — system findings banked during the run

  • fixed049 rolled-writer union emitted duplicate tree entries when a v0.6.0 CLI had auto-pushed an old-shape ref at the same path; GitHub fsck rejected the push. Fixed with name-dedup (buffer wins), failing-first test, committed c159d3d6 by the GPT-5.5 peer, pushed; re-sync healed all four sessions' refs and undid the v0.6.0 clobber (full segment sets now remote).
  • openflow-eval's base-ref drift warning string-compares the worktree HEAD sha to the tag name without resolving it — every correctly-pinned run gets a spurious warning.
  • openthe compare board renders lane verdict unknown as a 0.00 pass rate — inconsistent with scoring, which excludes unknowns; a blind telemetry lane reads as universal failure.
  • openold-base scenarios structurally blind the telemetry lane (no PIJ_SESSION_ID in segments); either bump bases or teach the scorer a harness-session fallback join.
