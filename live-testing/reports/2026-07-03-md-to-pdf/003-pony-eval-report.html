Editing the eval packet instead would contaminate the mandate variable and break cross-batch comparability. If adopted, a re-run cohort gives a clean A/B on a new seed tuple.

What minimalism did to verification

The task's "validated output" clause met four very different answers — all deterministic, none a file-size gesture, but with a real quality spread:

  1. output-proofFable 5 — the page writes mdpdf-ok-⟨n⟩ into document.title only after mermaid.run() resolves; Chrome copies it into the PDF's /Title; the validator reads it back from the PDF bytes and cross-checks n against the source fence count. Render fidelity proven from the artifact itself, near-zero mechanism.
  2. output-proofSonnet 5 — pdfimages counts embedded raster images in the produced PDF against the source's mermaid fence count; fewer diagrams than fences → exit 1. Chose PNG over SVG after measuring that non-browser SVG→PDF paths silently drop mermaid's foreignObject labels while still "succeeding".
  3. render-proofOpus 4.8 — subprocess validates %PDF- signature, %%EOF trailer, pdfinfo page count, and that every fence produced a non-trivial SVG. Proves the renders happened; does not prove they landed in the final PDF.
  4. structure-onlyGPT-5.5 — mmdc hard-fails broken diagrams; pdfinfo asserts valid PDF + pages ≥ 1. Open question raised by Sonnet's measurement: GPT-5.5's pipeline is exactly the SVG→weasyprint path Sonnet measured as label-dropping — its PDF may carry label-less diagrams while validating "ok". Unverified (worktree torn down); worth a probe if this extension graduates.

Insights, ranked

01

Minimalism bought capability 1.00 at the lowest cost ever recorded on this task

Four working, validated extensions; zero new dependencies across the entire cohort; ×0.40–0.86 of blind credits and ~⅕–⅓ of flow credits. On pure task economics, ponytail wins this task outright.

Evidence: cohort table + cost triangle above; ledger runs 050238Z/050744Z/051424Z/051428Z.
02

Verification did not collapse — it stratified by model personality

Two of four built output-proof validators arguably stronger than some flow-cohort backpressure designs. But the floor dropped too: the cheapest run's validator can't see a diagram that silently lost its labels. Under minimalism, verification quality is whatever the model's own culture supplies — the doctrine neither mandates nor forbids it.

Evidence: validator panel; Sonnet's measured foreignObject label-drop; A14 judged rows all pass with graded caveats.
03

The harness loop is ponytail's blind spot — the standing watch is confirmed

0/4 observe, 0/4 retro, 0/4 loop seams, while the same models under no doctrine at all used the sensor surface more. YAGNI classifies the improvement loop as optional mechanism. The fix belongs in the skill's own carve-out list, not in eval packets.

Evidence: conduct matrix (raw-event ground truth); batch-1 sensor baseline; observe buffer CONF-001.
04

The instrument under-samples exactly the cohorts it most needs to see (DL-005)

Command-anchored capture windows mean a frugal subject is nearly invisible to the telemetry lane. Every deterministic skill-lane fail this batch was a capture artifact, not conduct — caught only because the runbook mandates raw-event cross-checks before judging.

Evidence: 1 segment vs 242 raw events (GPT-5.5); 1 segment vs a full transcript (Fable); Opus captured 9 segments only because it ran 38 harness commands.
05

Model personality persists through any doctrine

Sonnet measured before believing (again — it was also the one that caught a security bug pre-code in batch 2). Opus architected cleanly and documented ceilings (and again treated bookkeeping as optional). GPT-5.5 sprinted to the leanest working thing. Fable spent its budget on one elegant design idea. The mandate changed the budget; it didn't change who they are.
