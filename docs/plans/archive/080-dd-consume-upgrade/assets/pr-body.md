## Read this before approving — two accepted degradations and one provenance note

These are known, ruled, and shipping deliberately. A reviewer should be approving these
trades knowingly, not discovering them later.

### 1. `plan validate`'s untracked-target message is less specific than the fork's was

| | |
| --- | --- |
| **Before** (fork, `services/dd/core/walk.ts:125`) | ``address target is not tracked by git: <path> — track it with `git add <path>` `` |
| **After** (package `a37a20ec`, `dist/core/walk.js:74`) | `address target is not tracked: <path>` |

The fork carried harness's own FX014 improvement (`4902fef7`); the package never took
it, so the weaker string has actually been live since the phase-1/2 rewire — the
deletion only removes the last copy of the better one. **Ruled by Jordan (2026-08-09):
"not tracked is fine, everyone knows what that means."** The framing that matters for a
future reader: FX014 had put *git vocabulary into dd's core*, a layering the fork
accepted invisibly and the package refused — consuming the package **revealed a
misplacement** rather than causing a regression. dd owns the mechanism wording;
harness owns the remedy, at the act layer, post-080.

### 2. The generated `.dd.md` banner names a command that resolves to a different program

Every generated sibling now carries `GENERATED by \`dd build\`` — a **defect in dd's
renderer, which dd is fixing**, not a spelling preference (the fork's said
`harness dd build`). Bare `dd` is **coreutils' disk-dump tool**
on every POSIX system. Worse, dd's `package.json` declares `bin: {dd}`, so a future
global install would *shadow* `/bin/dd` and silently break raw-device scripts.

**Ruled: ships as-is with this note.** The closer is not a spelling fix — Jordan routed
the **dd CLI naming question** to the dd team (rename must land *before* their first
release; it becomes a breaking change the day after). The banner text follows whatever
name they choose. Today the only prescribable invocation is `node_modules/.bin/dd`:
unscoped `npx dd` fetches a **stranger's squatted package**, and scoped
`npx @ai-substrate/dd` is a 404 until Jordan publishes.

### 3. Where the fork deletion physically lives (`git log` will mislead you)

| commit | what it actually contains |
| --- | --- |
| `237ab2e1` | the **logical** deletion commit — rewires, test conversions, 22 banner-only regens |
| `7d112d26` | **261 fork file deletions** (subject reads "ledger #5 — FX014") |
| `2b5a07af` | 2 generator scripts |
| `430f1511` | the 10 documents that also owed a `satisfies_toward` column since `57d8bd1f` |

In a worktree shared by several agents, one seat's `git add <paths> && git commit`
commits the **whole index** — pathspec discipline on the *add* does not protect the
*commit*. The coder's staged deletions were swept into a PM ledger commit minutes later.
**Ruled accept-not-rewrite**: nothing was pushed, but rebuilding seven commits under an
active coder risked the evidence chain for a provenance nicety that squash-merge
collapses anyway. The ordering proof that matters survives:
`merge-base --is-ancestor 8e9d1ecf 7d112d26` — the fork-drain checklist precedes the
deletion. Practice adopted: `git commit -- <paths>` in shared trees.
