## Problem

The test's worker prompt (`agents/validate-harness-flow/prompt.md`, 256 lines) is a complete runbook: install commands incl. the npm `--prefix` workaround, the skill names and their output file paths, the abandonment grade bands, expected envelope semantics, and a step order (S0–S6). Four consequences:

1. **It measures the wrong thing.** A worker given a perfect runbook proves "an agent can execute a runbook." It cannot detect onboarding regressions — if `harness instructions`, the READMEs, or the skill chain rotted, the test would still pass. The product's real onboarding chain (repo `README.md` → `skills/README.md` "The intended loop" + "Operating rules" → the mounted `eng-harness-*` skills, which self-describe and chain to each other) is never exercised.
2. **It drifts.** The prompt is a 4th independent copy of product knowledge — and it has already drifted: it still mandates the hand-written 8-BIO-field governance doc the product itself deferred (`skills/README.md`: setup "writes no governance doc — owned by a future `harness init`"), and its S5 predates `harness observe` (instructs hand-filling the retro, now the anti-pattern).
3. **Grading is self-report.** PASS/FAIL rests on worker-set booleans (`governanceWritten`, `bootRuns`, `retroRecorded`) the 575-line extension merely renders. Nothing verifies the clone.
4. **The documented path is unmountable.** The extension's `SKILL_FLAGS` sends only 3 skills (assessment, add-extension, retro). The documented entry point `eng-harness-0-setup` — and `eng-harness-1-boot`, whose `UNAVAILABLE` verdict routes to it — are not mounted, so a worker could not take the onboarding path even if briefed to find it.
5. **The skills surface is never installed in the clone.** The documented intended loop's step 1 ("Install the skills" — `skills/README.md`) is neither performed (the worker leans on the minih mount) nor verified. The clone ends the run without a project-local skills install, so it is not actually self-sufficient for the next agent that opens it — and the product's own skills-install journey (`npx skills` / `harness skills install`) goes untested.

**Decided direction** (user, 2026-06-10): pure goal brief — "imagine this is installed on a new machine and we need folks and agents to be able to figure it out and get it going"; governance requirement removed from the test entirely; **no** observe hint in the brief — if workers miss the verb, the fix lands in product docs/skills, never the briefing; runbook **replaced** outright (git history keeps it); the `--prefix` trap encoded product-side.

## Proposed Fix

Three moves: (a) the brief shrinks to a goal + test plumbing; (b) the test's rules stay with the worker but stop leaking product knowledge; (c) grading inverts — the extension probes the clone deterministically, with the worker's self-report kept as an advisory cross-check (no verdict-ownership redesign in this fix).
