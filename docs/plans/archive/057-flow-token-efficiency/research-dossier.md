## Answer

1. The flow's structural token costs sit in three tiers: a **~110–120KB fixed read set at every guided entry** (builder SKILL 20.6KB + 00-routing 44.9KB + coach 43.8KB + flight-plan-ops 9.6KB), a **per-call CLI envelope duplication** concentrated in JSON mode (~230B near-identical `data` block per mutation verb; 1.1–1.5KB per 5-call sequence), and **unguided premium-model spend** (six worker-spawn sites across the stage modules carry zero model-tier or subagent guidance).
2. The cheapest, proven encoding channel for 057's guidance is **per-node `instructions[]`** in the flight-plan template (80–193B/line, auto-cloned to every phase by the expander, re-read every turn via `orient`) — the exact mechanism 056 used for the posture line; boot-file additions cost ~1000× more per session.
3. The CLI fixes are small and localized: all mutation verbs funnel through one `summary()`/`runMutation()` (single-point envelope slim), but no quiet/verbosity mechanism exists anywhere — a `--quiet` is new surface; `orient` is a separate code path whose `instructions[]` payload is the true per-turn cost.
4. **Measurement is the trap**: session-level token baselining works today (TurnEvents carry full buckets + model; 056 = 59k in / 182k out / 64 min), and shipped tooling (`flow_stage` lens, `stageEconomics` insight) already computes per-stage cost — but the real 056 capture is **FlowEvent-starved** (2 events, whole run collapses to `unlabeled`), and nothing in either skill emits stage-transition FlowEvents. Per-stage verification needs a capture-density fix first.
5. Token doctrine is currently **builder-only** — eng-harness-flow's SKILL/routing/coach files carry none of it; with both skills in scope, 057 must decide mirrored-citation (doctrine-parity pattern exists) vs a lighter one-line cite.
