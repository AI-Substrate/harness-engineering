## Answer

1. The asked-for command is the **anticipated "offline recurrence analysis"** the retro substrate was explicitly designed to feed: drains write *every* presented entry — including `declined`/`deferred` dispositions — to committed records precisely so a later cross-plan analysis can see what we said no to (F-05, H-04). Nothing occupies that seat today.
2. The closest existing capability is the retro verb's `--harvest` mode: it already scans `.harness/records/retro/**`, clusters by `(kind, target)`, and prioritizes top-10 by recurrence → severity → back-pressure leverage → age — but it is **skill-side inference**, re-paid in tokens every run, single-shot, and cites a machine consumer (`scripts/compound-value.sh` / `just compound-value`) that **does not exist** (F-02, F-08, H-06).
3. The repo has a locked architectural template for exactly this shape: plan 048's insights layer — **deterministic generators in a pure CLI service compute every number; the LLM narrates prose only** ("the LLM never computes a number that appears in a report"). Plan 056 already shipped two retro-cohort generators (`observe_conversion`, `disposition_mix`) plus tripwire thresholds to compose (H-01, H-02, F-06).
4. The input contract is frozen and sufficient: retro schema v1.2 records carry `plan_id`, and entries carry `kind`/`target`/`severity`/`disposition`/`fp`/`system.compound.status` — recurrence joins on `(kind, target)` (+ `fp`), lifecycle exclusion reads `compound.status`, and "keeps getting deprioritized" reads repeated `declined`/`deferred` (F-03, F-04, H-03).
5. Routing: the five lifecycle hooks are **frozen** — the new capability ships as a deterministic `harness` CLI verb plus an eng-harness-flow verb-module/`at=` surface reached through existing hooks (harvest already lives at `post-flight`), never a sixth hook (H-05).
6. Output posture is constrained by a frozen KISS decision: **no committed ledger/rollup/index** — the report is a recompute (terminal/JSON/HTML), regenerable in <1s-class time, not an on-disk dashboard that drifts (H-06 §D4).
7. The corpus is real and ready: 35 records, 182 entries across 22 plans; 133 entries still `open` vs 23 `encoded` / 26 `suggested` (as of 2026-07-12; corrected from an initial under-merged scan) — the open backlog this command exists to rank (F-07).
