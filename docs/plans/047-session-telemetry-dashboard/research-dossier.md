## Answer

1. **The command surface is a copy-paste seam, not new plumbing.** All telemetry verbs register inside one function (`registerTelemetryAct`, commander-based); `get` (positional arg + flag + async handler) is the exact pattern to copy for `session save <id>` / `report <paths…>`. No change to the mount site (`app.ts:270`). Handlers already get `fs.writeText/mkdirp/rename`; add `fsWrite` to the deps interface for the richer `copy`/`mkdtemp` surface.
2. **The OTLP input contract is frozen and must be *read*, never re-mapped** (plan 038): reconstruction-critical data rides under `harness.*` pinned by our `schema_url`; only two `gen_ai.usage.*` token names are adopted semconv. **Logs are the lossless substrate; metrics are derived/lossy.** `segmentToOtlpLogs` has an exact inverse (`otlpLogsToEvents`); `rollupToOtlpMetrics` has **none** — so the combine algorithm regenerates *both* OTLP signals *forward* from a `<seq>.json` segment, and any cross-session rollup re-aggregates **from Logs**, never by summing per-session cumulative metrics.
3. **Reuse the production rollup engine, not gen.py.** `computeRollup` (rollup.ts:135, `IDLE_CAP_S=300`) is the real rollup; gen.py is reference-only and uses a *different* idle cap (1200s) and reads the transcript, not `event_stream`. The report's rollups (incl. flow-stage time/tokens) build on `computeRollup` + `fold` semantics.
4. **The export/combine/multi-session-report/HTML layer is genuinely greenfield** — nobody has combined segments, rolled up across sessions, or rendered telemetry to a document. Two seams don't exist yet: a **committed-shard git *read*** path (only local `rev-parse` peels exist), and any **HTML render**.
5. **The reference HTML embeds its JSON inline** (`<script type="application/json">`, no `fetch` — `file://` CORS-blocked). So "the HTML renders whatever report is in its folder" = the render step **inlines** the folder's report JSON into a template copy at generation time (the gen.py pattern) — same UX as workshop 002 describes, but the mechanism is inline-embed, not runtime fetch. **002 needs that one correction.**
6. **Hard rails (frozen, plan 034/037/038):** git read-only (working tree byte-identical; read committed telemetry from orphan `refs/harness-telemetry/*` only); counts-only/allowlist privacy floor extends to any committed HTML/report/golden (byte-scan + scrub); dodge the `*.log` gitignore trap; render known-degraded cells (subagent tokens, `plans_touched`, out-of-repo paths) honestly.
